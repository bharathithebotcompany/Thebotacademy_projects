Sila questions-ku answer oru single document-la irukkaadhu. Multiple documents connect pannina dhaan final answer kidaikkum.

Idhukkudhaan Multi-Hop Retrieval.

Hop-na retrieval process-la oru information search step.

For example, oru user "Project X-ai manage panra team lead yaar, and avar report panra department head yaar?" nu kekkuranga.

First, Project X pathi search panni team lead name find pannanum.

Next, andha team lead-oda reporting information-ah search pannanum.

Appuram department head name retrieve pannanum.

Rendu retrieval steps connect aagi final answer create aagum.

Idhu dhaan Multi-Hop Retrieval.

Basic RAG-la single query retrieve panni answer generate pannuvom. Multi-Hop approach-la first retrieval result next search-ku input-ah use aagum.

Indha approach relationship-based questions, multi-document comparisons, and connected facts retrieve panna useful-ah irukkum.

Inga important challenge enna-na, first hop wrong-ah irundha second hop-um wrong direction-la pogalaam. Adhanaala each stage result-ai validate pannanum.

Query Decomposition-la complex question-ai sub-questions-ah split panrom. Multi-Hop Retrieval-la one retrieval result-ai next retrieval step connect panrom. Rendu related concepts, aana same process illa.

Ippo system multiple steps retrieve pannudhu. Aana retrieved information sufficient-ah irukka-nu system itself reflect panni decide panna mudiyuma? Adhukkudhaan Self-RAG.
